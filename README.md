# APEX-3D 封裝試點線

CoWoS 類（Chip-on-Wafer-on-Substrate）先進封裝**培訓原型**。虛構廠區「APEX-3D 封裝試點線」，產品 HBX-100。不是任何真實晶圓廠或原廠產品的數位雙生，也不會寫回 MES / ERP。CoWoS 只是工藝族通稱。

v3 仍是下面這五站。譜系、MES 狀態、3D 形態、電子倉庫與天車都讀 `js/route.js`。倉庫和天車是廠務，不是第六站。

| 站 | 載具 | 進來 | 這一站改變的東西 | 出去 | 在這裡凍結的 HOLD |
| --- | --- | --- | --- | --- | --- |
| 1 來料／KGD 晶粒倉 | FOUP，加上機台上的晶粒倉托盤 | 來料晶圓、還在倉裡的裸 KGD | 檢查並發料。還沒有疊晶 | 已發料、可以去鍵合的 KGD | KGD 短缺：晶粒不發，不能進疊晶形態 |
| 2 CoW 混合鍵合 | FOUP＋目標中介層晶圓 | 已發料 KGD＋目標晶圓 | 混合鍵合介面；疊晶落到晶圓上 | 看得到鍵合面的 CoW 疊晶 | 鍵合偏移：疊晶偏離目標，不能進切割後的形態 |
| 3 切割 | 切割框架／藍膜 | 已鍵合的 CoW 晶圓 | 單顆化 | 一顆顆 CoW | （沒有本站專屬 HOLD） |
| 4 WoS | 基板 magazine | 已切割的 CoW | 疊晶坐上封裝基板 | CoW-on-substrate | 基板翹曲：組裝留在本站，錫球不出現 |
| 5 植球／終測／包裝 | JEDEC tray | WoS 組裝 | 錫球長出，測試，放入 tray | 已植球、測完、入盤 | 底部填充空洞：不完成已植球入盤的形態 |

相對 v1 收過的欄位：空洞 HOLD 放在第 5 站；鍵合偏移在 HB-21 重做，這條路線沒有電漿站；第 2 站的「晶圓」是中介層，封裝基板到 WoS 才進 magazine；切割載具代碼是 `FRAME`。3D 用一顆主疊晶加三顆同伴表示單顆化，批次紀錄仍是 12 個 site。

## 電子倉庫

走道西端一座自動倉（AS/RS），不是製程站。四個庫區在同一個櫃體裡，貨位有貨或空位一眼可以分出來：

| 庫區 | 放什麼 | 載具 |
| --- | --- | --- |
| DBK | KGD／晶粒倉托盤 | TRAY |
| INT | 中介層 FOUP | FOUP |
| SUB | 基板 magazine | MAG |
| FG | 完成的 JEDEC tray | TRAY |

庫存狀態是 `在庫 / 預留 / 在途 / 鎖定`。位置另記：貨位、出入庫口、堆垛機、天車、工位裝載口、已交接。右側倉庫面板是學員看電子倉庫的地方，和 3D 貨架是同一份紀錄。

運作（程式裡真的這樣跑）：

- 第 1 站開始前，倉庫要發出 DBK 的 KGD，以及 INT 的中介層 FOUP。基板 magazine 留到 WoS 之前才發，不會在第 1 站發。
- 包裝完成後，成品 tray 入 FG。
- DBK 沒有未鎖定、數量大於 0 的 KGD 時，出庫直接拒絕。批次停在 KGD 短缺，天車不會把一台沒發出來的載具帶走。
- HOLD 開著時，材料可以退倉，或鎖在當站裝載口。不會被送到下一站。
- 載具位置以倉庫紀錄為準。天車有沒有吊著、機台裝載口有沒有貨，都要和這份紀錄一致。

堆垛機在貨位和出入庫口之間緩動。天車只在出入庫口耦合，不從貨架裡直接撈。

## 天車

天軌是單向迴路，連接倉庫出入庫口和五站裝載口。畫面上的名字是天車，OHT 是副標。兩台車，狀態：`空閒 / 前往取貨 / 取貨升降 / 搬送中 / 放貨升降 / 暫停`。

運作模式是可以切的，不是標籤：

1. **自動派車**：預設，自動走線也用這個。製程完成或倉庫出庫會產生搬送需求，空閒的車會被派出去。
2. **手動叫車**：不自動派新的任務。學員指定來源和目的，或按「派這一趟」。已經派出去的那一趟會做完。
3. **暫停**：不再派新任務。正在升降的那一下可以做完，然後車停住。HOLD 開著時，車可以做完當下的升降，或把載具退回倉庫，但不能把貨送到下一站。

一趟搬送：建立需求 → 空車走到來源 → 下降耦合（此時倉庫把載具改成在途）→ 沿天軌走（載具跟車）→ 到站下降脫鉤 → 車回空閒。交接進機台之後，製程動畫和產品形態才開始。載具類型和目的地不符就拒絕，並寫進出入庫紀錄，不會硬靠上去。兩台車不會疊在同一段天軌上，必要時在側線等。

走完一站之後，載具留在裝載口等天車來取，不會直接出現在下一台機。

## 怎麼打開

本頁是 ES modules，請用靜態伺服器，不要用 `file://`。

```bash
cd cowos-packaging-sim
python3 -m http.server 8765
```

瀏覽器開 <http://127.0.0.1:8765/>。介面預設繁體中文，可切簡體與 English。Three.js 在 `vendor/`，不需要外網。

點底列任一站可單獨重播該站（先把載具從裝載口交進機台，機台才動，不推進批次）。空白鍵走站，R 重播當前站。自動走線會連倉庫出庫、天車和機台動畫一起播。F 跟隨批次，3 跟隨天車，1 回到能同時看到倉庫、天軌和五站的總覽。

## 驗證

邏輯（不需 WebGL）：

```bash
node --experimental-detect-module test/acceptance.mjs
```

這支腳本檢查五站合約、形態連續、良品批走到 `packed`、四個 HOLD 的凍結點，以及 v3 的廠務規則：出庫／入庫／退倉、KGD 短缺會拒絕出庫且天車不取貨、三種天車模式、沒靠港不能開製程、HOLD 擋下一站、載具類型不符會拒絕、倉庫位置和天車／機台一致。

瀏覽器（本機 `python3 -m http.server 8765`）：

1. 開批後看倉庫：四個庫區、貨位、右側的儲位／批次／載具／數量／狀態，以及出入庫紀錄。
2. 推進一站。天車先到出入庫口下降取貨，載具跟著車沿天軌走，到裝載口放下之後機台才開始動。
3. 點底列可以重看鍵合、切割、植球的機台姿態。
4. 問題選「多」：DBK 鎖住或是空的，出庫被拒絕，天車停在原處。鍵合偏移時，載具留在 HB-21 或退回倉庫，不會進到切割站。
