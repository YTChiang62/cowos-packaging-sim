# APEX-3D 封裝試點線

CoWoS 類（Chip-on-Wafer-on-Substrate）先進封裝**培訓原型**。虛構廠區「APEX-3D 封裝試點線」，產品 HBX-100，流程代號 `HBX-100-COWOS-S`。不是任何真實晶圓廠或原廠產品的數位雙生，也不會寫回 MES / ERP。CoWoS 只是工藝族通稱。參數是公開參考模板的行業典型值，不是量產配方。

v12 把 HBX-100 改成參考模板的 **5 Module · 18 Stage · 86 Step**。五個製程區對上五個模組，沒有第六個園區：M1 中介層製備、M2 晶圓與載板準備、M3 CoW 鍵合、M4 oS 組裝、M5 封測出貨。製程是 μBump + TCB，不是混合鍵合。同一類設備共用一台 3D 機台。CoW 重構晶圓整片貼上 ABF 載板，HBX-100 不再把鍵合後切割當成必經工步。譜系、節拍、配方、倉庫與天車仍讀 `js/route.js`（配方在 `js/recipes.js`）。沒有第二套狀態機。

v13 是第二階段，把異常和機台狀態變成可以在現有畫面上操作的現場工作，不改 5/18/86，不加第六園區，也不做角色任務或評分。34 台共用機各有運行、待機、輔助、當機、保養、驗證；當機、保養、驗證不會對靠港批次開工，輔助要先解除。原來的四張 HOLD 先圍堵，再選重工、報廢或放行。重工仍回到原來的站（鍵合偏移 s324、空洞 s332、翹曲 s412）。報廢會結束這批，不當良品入盤。M5 終測留下訓練用的良率與分級。派工預設先到先做，可以把批次標成急批。班次卡仍是週期、產出、可用率，下面多一行當班目標對實際。天車按鈕仍是自動派車、手動叫車、暫停。

編號正文是 83 步。1.4.2 光刻／蝕刻、1.4.3 濺射／電鍍、1.4.8 回流／清洗各拆成兩個工步，所以可執行流程是 86 步。封面表上的 22／17／16／15／16 和編號正文對不上；訓練線跟編號工步。

## 和 v3 的合約差異

- 電漿是這條路線上的機台（PLS-11）。v3 寫過「這條路線沒有電漿站」，v4 取消那條註記。
- 鍵合偏移改在疊對量測 MET-23 偵測，不再掛在 HB-21。重做回到混合鍵合，再退火、再量測。電漿可以重跑，預設不重跑。
- 底部填充空洞改在點膠 UF-05 發生，不再掛在植球／終測／包裝。重做只重點膠。
- 翹曲改在 MET-07 量測，不再只在 WOS-04 偵測。重做回到 WoS，再點膠、固化、量測。
- 形態多了減薄、已固化填充、已植球：`bank → issued → bonded → thinned → singulated → wos → underfilled → balled → packed`。
- 每步正好一台設備、一張配方。配方是物件，帶 3–6 個參數（名稱、數值、單位），不是只有代號。

## 電子倉庫

走道西端一座自動倉，四個庫區：

| 庫區 | 放什麼 | 載具 |
| --- | --- | --- |
| DBK | KGD／晶粒倉托盤 | TRAY |
| INT | 中介層 FOUP | FOUP |
| SUB | 基板 magazine | MAG |
| FG | 完成的 JEDEC tray | TRAY |

FRAME 不是庫區。貼膜上框時，FOUP 退回 INT，FRAME 在 MNT-80 出現，一直當批次載具，直到 WoS 這邊換成 tray。空框架留在 WOS-04 的單元口，不入庫。

庫存狀態是 `在庫 / 預留 / 在途 / 鎖定`。位置另記。

- 來料檢驗先領 INT 的中介層 FOUP。來料區不發基板。
- 晶粒倉要處理之前，必須發出 DBK 的 KGD，並且中介層 FOUP 已經在手上。DBK 沒有可發的 KGD 時，出庫直接拒絕，天車不會取走沒發出來的托盤。
- 基板 magazine 在基板預烘之前才從 SUB 發出，不是在晶粒倉發。
- 入盤之後，成品 tray 入 FG。
- 區內工步之間用天車搬，不瞬移。

## 天車

天軌是單向迴路，每一台製程機都有裝載口。兩台車。模式沿用 v3 的說法：**自動派車**、**手動叫車**、**暫停**。

一趟搬送：建立需求 → 空車走到來源 → 下降耦合（這時才改成在途）→ 沿天軌走 → 到站下降脫鉤 → 交接進機台之後，製程動畫和形態才開始。載具類型不符就拒絕。HOLD 開著時可以做完當下的升降，或把載具退回倉庫，不能送到下一台製程機。

## 底色

右下角相機列上方有「底色」，三個預設，切過去立刻改 3D 場景，不用重新載入：

- **淺色潔淨室**（預設）：近白地板、柔和白晝天空，霧很淡，遠端製程區仍清楚。機台櫃體是中間調，載具和參觀的人在淺色地板上仍分得開。
- **中性灰**：介在淺色和深色之間的廠房灰。
- **深色**：沿用 v5 的深底（清色／霧 `0x071016`、原來的地板和燈光）。

選擇存在瀏覽器 `localStorage`，鍵名 `apex3d-theme`。沒有存過、或存的值不是這三個之一，就用淺色。會改天空、霧、地板、製程區色塊、牆、裙板和燈光。不會改機台位置、21 步流程或配方。步行、跟隨批次、跟隨天車、總覽都用同一套底色。

## 廠區平面

總覽是略帶俯角的潔淨室平面，不是正上方的二維圖。五個製程區畫成界線清楚的色塊（來料、CoW、切割、WoS、植球終測）。製程列南北外側各有一條回風夾道。周邊是空調機房、靠倉庫這一端的更衣室，和一間小值班室。電子倉庫仍是唯一的物料倉。製程內容沒有改：還是這 21 個工步、原來的機台和兩台天車，沒有前段製程區，也沒有第六個製程園區。

## 廠況

總覽上多一層廠況，不改 21 步流程，也不改機台位置。五個製程區各有一塊浮標，寫區名和負載百分比；有排隊就標隊數，有 HOLD 就標報警。沒在忙、沒排隊、也沒報警的機台不掛浮標，避免 21 台一起鋪上來。步行或看當前站時，靠近的那一台會多一行原因。浮標不是實體，人走在走道上不會被擋住。空調機房、更衣室、值班室和回風夾道沒有製程負載。

瓶頸卡在電子倉庫面板左邊，不壓到左邊的來料和更衣室。卡片下面有「廠況」，可以分別開關負載、報警、排隊、當前。預設前三項開著。選擇存在瀏覽器 `localStorage`，鍵名 `apex3d-ops-layers`。天車的叫車按鈕留在倉庫面板裡，不跟這排開關疊在一起。

一行建議，最多兩個數字。優先順序是：開著的 HOLD、最長的排隊、負載到了 80%、天車暫停。晶粒倉缺料算在來料，不會變成別的機台當機。天車暫停只當成搬送還停著，先恢復自動派車，不會憑空給製程機掛報警。數字跟著訓練批和經過的時間慢慢變，同一個狀態下是確定的，不會每一幀亂跳。

## 產品目錄、開批方式、可移動面板

這條線可以開三種虛構訓練品，仍是同一套狀態機。開批時選定一種，批次就只走那一條流程。

- **HBX-100 中介層封裝**（預設，`HBX-100-COW-WOS`）：原來的 21 步、配方、形態、HOLD、倉庫與 FRAME 規則。資料仍在 `js/route.js` 與 `js/recipes.js`。
- **HBX-240 高帶寬存儲堆疊**（`HBX-240-COW-WOS`）：同一組 21 台設備、同一套靠港與 FRAME 規則。KGD 發得更多，疊對和翹曲上限更緊，錫球數、終測程式和印字不同。
- **HBX-S12 單晶粒基板封裝**（`HBX-S12-SUB`）：約 13 步。已單顆化的 KGD 直接上基板，不走 CoW 混合鍵合、不切割、沒有 FRAME、不領中介層。INT 還在倉庫裡，這批不用。CoW 和切割機台留在現場，天車不必去。

進來先看到廠區和右側產品目錄。點一張卡片看工步、用到的製程區和主要用料（中介層、KGD、基板、錫球），再按開立訓練批。批次不會自己走，要先選 **一次自動跑完** 或 **逐步推進**。自動打開既有的自動走線（含靠港後才加工）。逐步讓自動走線保持關閉；空白鍵或「推進本工步」做完當前工步（含等天車）後停下。HOLD 仍會停下來等處置。再開一批回到目錄。

節拍列是準備、運輸、進站、加工、出站、過帳。

批次、倉庫、機台、流程列、瓶頸卡、廠況、底色、鏡頭、節拍和呼叫面板可以拖標題列移動，也可以收起。收起後從畫面上方中間的面板條打開，不會擋到來料這一端。專注畫面會把大面板收起來，再按一次恢復。位置和隱藏狀態存在 `localStorage`，鍵名 `apex3d-hud`。拖曳從面板標題開始，不會變成步行的障礙，也不會搶走軌道相機或步行視角。廠況浮標仍不是實體。天車按鈕留在倉庫面板。

## 班次、同伴批、情景、版面

開批之前可以選一個情景。選了之後，倉庫、HOLD 或天車會先停在那個狀況，不用自己去找。

- **首批**：不預埋 HOLD，天車維持自動派車。
- **KGD 缺料**：晶粒倉鎖住，這批在晶粒倉就會被拒絕出庫。
- **鍵合偏移**：這批已經停在 MET-23。HBX-S12 沒有 CoW，這個情景不會出現。
- **翹曲**：這批已經停在 MET-07。
- **天車暫停**：兩台車維持暫停。先恢復自動派車，不會把製程機當成當機。

現場另外看得到 2 或 4 個同伴批（問題選「多」的時候是 4 個），是小的產品模型，停在目前機台或裝載口。可以點它們，或點班次卡上的短名單。跟隨批次會跟著選到的那一批。同伴批不另開一條廠務狀態機，也不會搶英雄批的天車。開著 HOLD 的時候，它們不會穿到 HOLD 下游。

右上附近有一張班次卡：週期、產出、可用率，下面一行當班目標對實際。目標是情景和產品的預設，不是排程系統。數字跟當前批、開著的 HOLD、天車暫停和廠況同一套時間桶，不會每一幀亂跳。卡片可以拖、可以收。派工預設先到先做；把一批標成急批後，切到急批會讓它插到忙碌機台或天車佇列前面，再切回去就恢復先到先做。

批次走完會多一段短復盤：發生了什麼、你做了或該做什麼，加上週期、HOLD 次數、可用率。再開一批仍回到目錄。HOLD 還是原來那張單。

鏡頭旁有三個版面，記在原來的 `apex3d-hud`：

- **廠長總覽**：批次和倉庫維持收起，留下班次卡、瓶頸卡和廠況開關，鏡頭回總覽。
- **跟批作業**：打開批次和機台，鏡頭改跟隨批次，班次和瓶頸留著。
- **步行巡線**：把大面板收起。它不會自己切進步行，也不會擋 WASD 或滑鼠視角。

專注畫面、從標題列拖曳、收起、從上方面板條打開，都還在。拖曳不會從 3D 畫面開始。

## 怎麼打開

本頁是 ES modules，請用靜態伺服器，不要用 `file://`。Three.js 在 `vendor/`，沒有新的執行期 CDN。

```bash
cd cowos-packaging-sim
python3 -m http.server 8765
```
